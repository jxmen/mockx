# domain-primer

사용자는 회원·계좌·입금 같은 일반 백엔드 도메인은 익숙하지만, 증권 고유 개념은 처음 접하는 단계다. 한꺼번에 많이 쏟아지면 막막해한다. 그래서 **개념 하나를 짧게, 실제 예시로, mockx에 필요한 만큼만** 설명한다.

설명만 한다. 코드나 문서를 쓰지 않는다.

## 1. 맥락 확인

설명하기 전에 빠르게 본다.
- 현재 브랜치와 최근 커밋 — 지금 어느 단계인지 (예: `feature/buy-stock`이면 주문 직전)
- 관련 `docs/db-design-*.md` — 이미 정한 것과 "보류"로 남은 것
- CLAUDE.md의 MVP 범위 — 미국 상장 종목(NASDAQ, NYSE Arca), USD, 지정가 주문, 내부 매칭

이미 문서에서 정한 내용은 다시 설명하지 않고 "이미 이렇게 정했다"고 짚는다.

## 2. 설명 형식

한 번에 개념 하나. 관련 개념이 줄줄이 엮이면 지금 필요한 것 하나만 설명하고 나머지는 "다음에 볼 것"으로 이름만 남긴다.

```
## 부분체결

**한 줄 정의**: 주문 수량 중 일부만 체결되고 나머지는 대기하는 상태.

**실제 시장 예시**
AAPL 10주 매수 지정가 $190.00
┌ 매도 호가 ───────────┐
│ $190.00  3주  (A)    │ ← 3주 체결
│ $190.05  20주 (B)    │ ← 가격이 안 맞아 대기
└──────────────────────┘
→ 체결 3주, 미체결 7주. 주문은 "부분체결" 상태로 남는다.

**mockx — 지금 최소한**
- 주문에 체결 수량(filledQty)을 두고, 상태는 PARTIALLY_FILLED 하나로 표현
- 예수금 hold는 미체결분만큼 유지

**mockx — 나중으로**
- 체결 건별 평균 단가, 수수료 분할 계산

**면접에서 나올 만한 질문** (1~2개)
- 부분체결 상태에서 취소하면 hold는 얼마나 풀어야 하나?
```

- **실제 시장 → mockx 최소 → 나중으로** 순서를 지킨다. 실제 시장 설명이 길어지면 표 하나로 줄인다.
- 숫자 예시는 mockx 기준(미국 주식, USD, 센트 단위)으로 든다. 한국 시장과 다른 점이 개념 이해에 중요하면 한 줄로 비교한다. (예: 한국은 가격제한폭 ±30%, 미국은 일일 가격제한폭 대신 LULD·서킷브레이커)
- 박스 그림이나 표를 쓴다. 기존 docs와 같은 스타일이다.
- 백엔드 구현 방법(코드, 클래스 구조)은 말하지 않는다. "테이블에 무엇을 저장해야 하는가", "어떤 상태가 필요한가" 수준까지만 간다. 구현은 사용자가 한다.
- DB 락·격리수준 같은 개념은 이 개념을 이해하는 데 꼭 필요할 때만 꺼낸다.

## 3. 정확성

여기서 설명한 내용이 설계 문서와 면접 답변으로 이어진다. 틀리면 그대로 틀린다.

- 규정·수치(호가 단위, 결제일, 장 시간, 서킷브레이커 기준)는 확실한 것만 단정한다. 날짜가 있는 사실은 기준 시점을 붙인다. (예: 미국 주식 결제일은 2024년 5월부터 T+1)
- 확실하지 않으면 `(확인 필요)`를 붙이고, 사용자가 원하면 웹에서 확인한다. 출처 URL을 지어내지 않는다.
- 증권사마다 다르게 하는 것(주문 상태 이름, 주문가능금액 계산 방식)은 "정답이 하나가 아니다"라고 밝히고 흔한 방식을 보여준다.

## 4. 결정이 필요하면

- mockx에 어디까지 넣을지 정해야 하면 **질문은 한두 개만** 한다. AskUserQuestion으로 여러 개를 한꺼번에 묻지 않는다. 대화로 하나씩 묻는다.
- 선택지마다 "지금 넣으면 생기는 일 / 미루면 생기는 일"을 한 줄씩 붙인다. 추천이 있으면 "추천: A — 이유"로 따로 쓴다. 결정은 사용자가 한다.

## 5. 마무리

- 설명한 개념과 "다음에 볼 것"을 한 줄씩 정리한다.
- 결정이 났으면 `design-note`로 문서에 남기자고 안내한다.
- 면접 질문이 나왔으면 `interview-drill`로 연습할 수 있다고 한 줄 덧붙인다.
