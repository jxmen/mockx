# interview-drill

면접에서는 "왜 그렇게 했나요?" 다음에 "그럼 이 경우는요?"가 이어진다. 이 스킬은 그 꼬리 질문을 미리 겪게 하는 것이 목적이다. **가르치기보다 묻는다.** 정답 설명은 사용자가 답한 뒤에, 사용자가 원할 때만 한다.

## 1. 주제와 근거 정하기

1. 사용자가 주제를 줬으면 그 주제로 한다. 없으면 아래에서 고르게 한다.
   - 최근 커밋(`git log --oneline -15`)과 `docs/`에서 주제 후보 3~5개
   - 기록 파일(`docs/interview-drill-log.md`)의 미해결 질문
2. 주제와 관련된 코드, 테스트, 설계 문서를 읽는다. 문서의 "면접 꼬리 질문 대비" 섹션이 있으면 그 질문은 이미 준비된 것이니 **그 다음 단계**를 묻는다.
3. 근거가 되는 위치를 첫 줄에 밝힌다. (예: "`account/Account.kt`의 hold/release와 `docs/db-design-account.md` 기준으로 묻겠습니다")

질문은 **mockx의 실제 코드에서 출발**한다. "트랜잭션 격리수준이 뭔가요?" 같은 교과서 질문보다 "`Account.hold`를 두 요청이 동시에 호출하면 `availableAmount` 검사는 어떻게 되나요?"가 실제 면접에 가깝고, 사용자가 지어낸 답을 할 수 없다.

## 2. 진행

한 번에 **질문 하나**만 던진다. 사용자가 답할 때까지 다음 질문을 쓰지 않는다.

### 질문의 단계

한 주제 안에서 아래 순서로 깊어진다. 사용자의 답에 따라 건너뛰거나 되돌아간다.

1. **무엇을** — 이 코드·결정이 무엇을 하는가
2. **왜** — 다른 선택지 대신 왜 이것인가 (트레이드오프)
3. **깨지는 경우** — 동시 요청, 재시도, 장애, 경계값에서 어떻게 되는가
4. **규모가 커지면** — 트래픽 100배, 서버 여러 대, 종목 수천 개라면
5. **실무 연결** — 실제 증권사라면 무엇이 더 필요한가 (규제, 정산, 감사 추적)

### 답에 반응하기

- **좋은 답**: 짧게 인정하고("맞습니다, 특히 ~를 짚은 게 좋습니다") 한 단계 깊게 묻는다.
- **얕은 답**: 정답을 주지 말고, 빠진 부분을 드러내는 구체적 장면으로 다시 묻는다. (예: "그럼 첫 요청이 커밋되기 전에 두 번째 요청이 잔고를 읽으면요?")
- **틀린 답**: 틀렸다고 분명히 말하고, 어디가 틀렸는지 코드나 반례로 보여준 뒤 다시 답할 기회를 준다. 맞장구치지 않는다.
- **모르겠다**: 힌트를 하나 준다(찾아볼 키워드 하나, 또는 생각할 장면 하나). 그래도 모르면 기록하고 다음 질문으로 넘어간다.
- 사용자가 "답 알려줘"라고 하면 설명한다. 이때 코드·문서 근거를 대고, 확실하지 않은 내용은 [추정]으로 표시한다. 일반론으로 지어내지 않는다.

### 면접관 태도

- 실제 면접처럼 담백하게 묻는다. 칭찬을 과하게 하지 않는다.
- 사용자의 설계를 공격하는 게 목적이 아니다. 지금 MVP에서 의도적으로 미룬 것(예: 복식부기, 다계좌)은 "왜 미뤘나, 언제 도입하나"로 묻는다. 결함으로 몰지 않는다.
- 질문 하나에 여러 질문을 섞지 않는다.

### 끝내기

- 기본 5~7문항, 또는 사용자가 "그만"이라고 할 때 끝낸다.
- 끝나면 아래를 보여준다.

```
### 결과: 예수금 hold (6문항)

✅ 잘 답한 것
- hold와 balance를 분리한 이유 (주문 가능 금액 계산)

⚠️ 보완할 것
- 동시 hold 경합: 경합 지점은 짚었지만 해결책 비교(비관적/낙관적 락)를 못 함
  → 키워드: `SELECT ... FOR UPDATE`, `@Version`

❌ 막힌 것
- 주문 취소와 체결이 동시에 오면 release가 두 번 일어나는가

다음에 다시 물어볼 질문 3개를 기록했습니다.
```

## 3. 기록

`docs/interview-drill-log.md`에 덧붙인다. 파일이 없으면 만든다. 기존 내용은 지우지 않는다.

```markdown
## 2026-10-19 · 예수금 hold

- 근거: `account/Account.kt`, `docs/db-design-account.md`
- ⚠️ 동시 hold 경합 — 해결책 비교 못 함. 키워드: `SELECT ... FOR UPDATE`, `@Version`
- ❌ 주문 취소와 체결이 동시에 오면 release가 두 번 일어나는가 — [미해결]
```

- 날짜는 오늘 날짜(절대 날짜)로 쓴다.
- 사용자가 실제로 한 답만 근거로 평가한다. 사용자가 하지 않은 말을 적지 않는다.
- 다음 세션에서 "지난번 막힌 거"를 요청하면 `[미해결]` 항목부터 다시 묻는다. 이번에 답하면 `[해결 YYYY-MM-DD]`로 바꾼다.
- 좋은 질문·답이 설계 문서의 "면접 꼬리 질문 대비" 섹션에 들어갈 만하면, 추가할지 사용자에게 묻는다. 묻지 않고 설계 문서를 고치지 않는다.
