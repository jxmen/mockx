# design-note

`docs/`의 설계 문서는 두 가지 역할을 한다. 구현할 때의 기준(테스트 기대값도 여기서 나온다)이고, 나중에 "왜 이렇게 했나?"에 답하는 근거다. 그래서 **무엇을 골랐는지보다 왜 골랐는지, 무엇을 포기했는지**가 남아야 한다.

## 결정은 사용자가 한다

- 선택지와 트레이드오프는 Claude가 정리한다. 고르는 것은 사용자다.
- 사용자가 아직 정하지 않았으면 "mockx의 선택" 섹션을 `결정 보류`로 두고, 결정에 필요한 질문을 적는다. Claude의 추천은 "추천: A — 이유"처럼 **추천임을 밝혀** 따로 쓴다. 추천을 결정처럼 쓰지 않는다.
- 사용자가 말하지 않은 결정 이유를 지어내지 않는다. 이유가 비어 있으면 묻는다.

## 1. 새 문서인지, 기존 문서 갱신인지

먼저 `ls docs/design/`와 관련 문서의 목차(`grep -n '^#' docs/design/*.md`)를 본다.

- 같은 도메인 문서가 있으면 그 문서에 섹션을 추가한다. (예: 출금 정책 → `docs/design/account.md`)
- 새 도메인이면 `docs/design/<도메인>.md`. (예: `docs/design/order.md`)
- 두 방식 비교가 중심이면 `docs/design/<주제>-<A>-vs-<B>.md`. (예: `ledger-single-vs-double-entry.md`, `lock-pessimistic-vs-optimistic.md`)

새 파일을 만들기 전에 경로를 사용자에게 알리고 진행한다.

## 2. 문서 형식

기존 문서의 규칙을 따른다.

- 제목 바로 아래 인용문으로 날짜와 관련 문서 링크를 쓴다. 새 문서는 `작성: YYYY-MM-DD`, 갱신은 `최종 수정: YYYY-MM-DD`. 날짜는 오늘 날짜다.
  ```
  > 최종 수정: 2026-10-19. 계좌 테이블은 [`account.md`](account.md)를 참고한다.
  ```
- 섹션은 `## 1. 제목`처럼 번호를 붙인다.
- 문장은 짧은 평서문(`~한다`)으로 쓴다.
- 데이터 흐름·테이블 상태는 박스 그림(`┌ ─ ┐`)이나 표로 보여준다. 기존 문서가 그렇게 한다.
- 다른 문서를 언급하면 상대 링크를 건다. 링크가 걸린 쪽 문서에도 역링크가 필요하면 함께 추가한다.

### 결정 문서 구성

모든 섹션이 필수는 아니다. 주제에 맞게 고르되 순서는 지킨다.

1. **상황 / 예시** — 구체적 예(회원 A가 10,000원 입금 등)로 문제를 보여준다
2. **선택지** — 각 방식을 같은 예시로 보여준다
3. **각 선택지의 문제** — 도입하면 생기는 설계 문제, 작업량
4. **비교 요약** — 표
5. **mockx의 선택** — 결정, 이유, 포기한 것, 나중에 바꿀 조건

### 도메인 설계 문서 구성

`docs/design/member.md`, `docs/design/account.md`를 따른다: 정책 → 테이블(컬럼·제약 표) → 요청/응답·입력 규칙 → 처리 흐름·클래스 구성 → 에러 응답(상태·`code` 표) → 범위 밖 → 테스트 → 작업 목록(체크박스) → 나중으로 미룬 것 / 알려진 한계.

- 에러 `code`는 대문자 스네이크 케이스, RFC 9457 Problem Details 기준으로 쓴다.
- 테이블 공통 규칙(단수형 이름, `DATETIME(6)` UTC, 제약 이름, Flyway)은 `docs/design/member.md` 2장을 참조하고 반복하지 않는다.

## 3. 정확성

설계 문서는 구현과 테스트의 기준이라 틀린 내용이 들어가면 코드도 그대로 틀린다.

- MySQL·JPA·Spring 동작을 설명할 때 확실하지 않은 내용은 `(확인 필요)`를 붙인다. 버전에 따라 다른 동작(예: MySQL 8.4의 기본 격리수준과 gap lock)은 버전을 명시한다.
- 출처·수치·URL을 지어내지 않는다. 실제로 확인한 링크만 쓴다.
- 문서 내용과 현재 코드가 어긋나면 어느 쪽이 맞는지 사용자에게 묻는다. 임의로 코드에 맞춰 문서를 고치지 않는다.

## 4. 진행 상황 갱신

"진행 상황 체크해줘", "작업 목록 업데이트"처럼 요청하면 작업 목록 체크박스만 갱신한다.

- 코드와 테스트를 확인해서 완료된 것만 `[x]`로 바꾼다. 테스트가 없으면 "구현은 있으나 테스트 없음"으로 표시하고 체크하지 않는다.
- 바꾼 항목을 목록으로 보고한다.

## 5. 마무리

- 쓴 파일 경로와 바꾼 섹션을 알린다.
- "결정 보류"로 남긴 질문이 있으면 다시 나열한다.
